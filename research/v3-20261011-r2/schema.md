# r2 本文再読・条件別抽出の契約

初回の `v3-development-review-r1` を保存し、追加記録は `v3-development-review-r2` へ分離する。基準は同じcodebook案で、補助条件・独立評価・実証済み効果を追加しない。

`condition-extractions.json` は人手（単一AI）が本文と条件を照合して書く入力。生成器は省略条件を埋めない。各選定記録に、共通8と型別70の異なる78条件を明示的に記入する。条件の欠落・重複・別作品の証拠参照は検査エラーにする。78は異なる条件ID数であり、26型の各行で繰り返される共通条件を二重に数えない。

各条件の状態はsupported、explicitly_false、unknown。いずれも理由と閲覧した根拠IDを記入する。unknownは本文を読んでも根拠が不十分である場合で、不出現だけを明示的否定にしない。unknownにも点検範囲を残すが、成立の根拠IDは空にする。処理前の作品はunextractedと明示し、unknown自動補完を抽出済みと数えない。

本文全体再読、対象箇所再読、各条件の抽出は別軸。全体は指定した掲載範囲を指し、原投稿一致・未確認続編・シリーズ全体の確認ではない。条件抽出完了も選んだ当事者・時点の78条件の点検完了で、作品の全場面抽出完了ではない。複数記録は同じ作品の場面であり独立標本に数えない。

証拠は短い自作要約に限る。URL・今回の本文確認ID・web reader上の行範囲・層を保持する。直接経験の叙述、夢、伝聞、信念、分析上の推論を区別する。型の必須条件と同じ当事者・時点の証拠を使用し、他人の症状や後の理解を本人の当時の予期へ補作しない。後からの訂正・照合は、過去の判断時に知っていた証拠と分けて説明する。

Fは旧前提、新証拠、及ぶ範囲、受容と脅威、局所説明の不足、代替仮説を本文から個別に抽出する。局所変更しか確認できない場合も具体的な記録を保存し、G3・G5等の不足によってF全体を保留できる。型別の証拠不明と一般的な陰性証明を区別する。

全131割当の進捗には初回の92指定本文・18限定範囲・21保留を保持する。保留解消は別のv3出典判断として記録し、継承した区分・v1原データを置換しない。未取得本文から当事者・場面を作らない。

同じ記録の必要条件が全てsupportedならfit、一つでもexplicitly_falseならnot_fit、それ以外pending。主型・副型も緩和しない。比較の対応は当事者・時点・範囲を明示し、旧場面と新記録の一対一を暗黙に仮定しない。

条件の不足理由が同じ場合は、`authorship_format: explicit_condition_groups` と `condition_review_groups` へ対象の条件IDを全て明示列挙する。列挙した判断だけを78行へ展開し、記入漏れは補完しない。各行と元の列挙の状態・理由・閲覧根拠の一致、全78条件の列挙を検査する。根拠や理由の共有を、未点検条件の自動unknown化や独立判断数の増加に使わない。

最終保存段階は `selected_scope_review_complete`。110作品すべてに少なくとも一つの選定記録があり、残り21作品はsource_hold。これは「全131割当の結果・保留が揃った」という意味で、全場面・全シリーズの抽出完了とは異なる。最終段階では非保留作品の取り漏れ、旧場面の対応理由の取り漏れを検査エラーとする。

`selected-record-results.json` は版ID・基準IDを持つ将来の表示用射影。v1比較には旧型ID・旧適合度、当事者と時点の対応区分、旧候補IDのv3必須条件結果、旧候補外の成立IDを記録する。同一IDを同一の定義として解釈せず、範囲重複の差を作品全体の型の追加・削除として表示しない。source_hold・場面未抽出・条件pending・明示的not_fitの表示を分ける。公開済みr1のデータ・現行切替へ自動接続せず、採用する版を明示する。
