# 独立評価の手順

設計段階・未実施です。以下は実施者が事前に合意する手順案です。未知本文の取得、募集、符号化、プレイは行っていません。

## 担当と実施の停止条件

語彙開発担当、資料管理担当、独立人間評価者、調停担当、解析担当を区別します。計画記録には匿名の役割IDと兼務を記します。評価者は全員人間で、同じ資料を独立に符号化します。AIの既存5群を評価者数に含めません。開発に関与した人の判定は補助解析へ分けます。

| Gate | 通過条件と保存物 | 通過できない場合 |
|---|---|---|
| G0 実施条件 | 参加条件、説明・同意、記録の用途、撤回と途中終了、匿名化、保管担当・期間を合意。評価者と参加者を手配 | 実施保留。今回はすべて未実施 |
| G1 語彙・解析固定 | codebook、型別必須・補助条件、場面区切り、rubric、尺度、抽出規則、必要N、解析・判定をcommit・SHA-256で固定 | 未決事項を計画記録へ残し、testを開示しない |
| G2 選定・独立性 | G1後に抽出枠を固定し、除外台帳と全候補台帳を保存。未知資料を管理担当だけが照合 | 同定や独立性不明は保留。件数から消さない |
| G3 配布 | 同一の版・範囲・場面IDを匿名化したパケット、割当表、閲覧権限、資料ハッシュを保存 | 期待型、AIラベル、challenge層が見える場合は配布保留 |
| G4 独立記録の封印 | 各人の記録とSHA-256、提出時点、未提出理由を保存。相互相談前の版を読み取り専用で保持 | 相談・ラベル漏洩を逸脱記録に残し、主解析から保留 |
| G5 合意前解析 | 独立記録のみから一致度と混同・欠測表を算出し、入力ハッシュと解析版を保存 | 調停済み値の代用は禁止。計算不能は保留 |
| G6 相違調停 | G5保存後に相違の根拠を確認。原判定を保持した別の調停記録を保存 | 根拠不足・範囲不一致は未解決のまま保持 |

G1以前の練習にはdevelopment資料を使います。練習の成績をtest結果へ混ぜません。testを見た後に語彙や閾値を変えた場合は逸脱を記録し、その資料を次版のdevelopmentへ移します。変更後の検証には別の未知資料と新しい固定記録が必要です。

## 未知資料の重複照合

管理担当は題名の正規化だけで独立性を確定しません。NFKC正規化、空白・表記揺れ・翻訳題・転載題の検索に加えて、人物、事件、設定、初出、エピソード範囲、転載元、系列、派生元を照合します。候補台帳の各除外区分に確認先と短い自作根拠を記録します。全文や長い引用は保存しません。

| 除外区分 | 照合する既存資料と対象 |
|---|---|
| development_131 | `assignments/groups.json`の131割当、`groups/*/data/mappings.json`の版・範囲・異名、`groups/*/sources/ledger.csv`の出典 |
| kotori_bako | コトリバコの本編・追加報告・再話・派生。割当131から除かれていても未知資料へ戻さない |
| legacy_examples | v1・v2・v3本文の全例示。エイリアン、Alien: Isolation、遊星からの物体X、CUBE、リング、イット・フォローズ、ウィッカーマン、SOMA、クトゥルフの呼び声と説明用例。これは照合の起点であり完全な異名辞書ではない |
| alias | 題名が違っても同じ話・翻訳・転載・再編集・題名同定候補に該当するか |
| derivative | 同一事件の再話、後日談、リメイク、開発例に由来する設計課題か |
| series | 開発資料と同じ系列・共通設定・集合伝承か。未知候補内でも同系列を一つのclusterに束ねる |
| prior_exposure | 定義の調整に使用済みか、評価者が本文や既存ラベルを既に知っているか |

各区分は`clear / match / unresolved`を記録します。一つでも`match`なら未知testから除外し、一つでも`unresolved`なら保留します。未同定や本文不足は「重複なし」に置換しません。版違いだけで独立作品に増やさず、開発資料の別版も除外します。照合担当と独立性確認担当が同じ場合は兼務と限界を残します。

候補の採否は`include / exclude / hold`で保存します。`include`には7区分すべての`clear`、対象版と範囲、本文確認、系列cluster、G1後の選定が必要です。未知本文の閲覧は将来の管理担当が行う作業です。このPRはその作業を実施していません。

## 頻度sampleとchallenge

頻度sampleは対象媒体・文化圏・期間・入手範囲を抽出枠へ記し、ラベルを理由に選びません。乱数手法・seed・候補の並び順・抽出確率・不採用理由を固定します。計画案では系列ごとに1作品を選び、全対象場面を記録します。固定した場面一覧から符号化前に1場面を乱数で選び、主一致度の単位とします。他の場面は補助一致度と作品内出現の集計へ残します。長い作品を多数の独立標本と数えません。有限の一覧から選ぶ場合の推定対象はその一覧の適格系列です。

challengeはD2、F1、F2、F3、F4の5層で、各層に支持候補と似た陰性候補を選びます。1系列の固定課題場面を1単位とし、複数場面を独立Nへ加算しません。候補層と期待は管理用台帳だけに保存します。符号化担当には開示しません。支持候補が実際に陽性だったという前提を置きません。各層の6支持候補・6陰性候補、計60系列は計画値です。開発資料と両セット間の重複系列も除きます。採れない層は未達・保留として残します。

challengeの適合比率を一般頻度へ足しません。頻度sampleで低頻度の型が出ない場合も、削除や一致成功を意味しません。境界比較はcodebookで固定された条件を使い、D2対D1・D5、F対局所的M更新などの相違を根拠ごとに残します。

## 独立人間符号化

同じ固定パケットを計画上3人へ割り当てます。題名・出典の秘匿は読解に必要な範囲と両立させ、各人は既知作品への気付きと盲検の破れを申告します。過去のAIラベル、他評価者の記録、管理者の期待、challengeの層は見せません。

最初に当事者、時点、世界層、対象、予期損失、Q、設定上／認識上のD、実行可能／認識されたC、Mを抽出します。次に型別必須条件の根拠を記し、A〜Eの主型・副型・候補とF群を別欄に判定します。根拠は位置指定と短い自作要約で残し、観測・伝聞・推測を区別します。閉鎖の設計案と本文中の達成も区別します。

26型すべてに判定を記録し、未評価欄は`pending`と理由を残します。`fit`には全必須条件の肯定根拠が必要です。`not_fit`には必須条件の明示的不成立が必要です。本文に記載がないだけなら`pending`です。補助条件の一覧が未固定なら`partial_fit`を使いません。型の記入を強制することと陽性を強制することは別です。

型なしの不気味さは`out_of_domain`、具体的問題はあるが既存型で区別が不足する場合は`unclassified_problem`、本文不足は`insufficient_material`として場面残余に保存します。F群だけ陽性の場面も認めます。F群では旧前提、新証拠、証拠範囲、当事者の受容・脅威認識、局所説明では足りない理由、代替仮説を残します。

場面区切り自体の再現性は別パケットで独立抽出します。同じ区切りを配布する主解析から、区切り一致を推定しません。区切り試験では型を見ずに開始・終了位置を記録し、固定した許容幅で境界のprecision・recall・F1を評価します。許容幅と必要Nが未固定なら区切り試験は保留です。

G5の解析を封印してから調停します。相違ごとに原記録IDとハッシュ、問題の条件ID、各根拠、裁定、残る不確実性を保存します。単純多数決だけで根拠不足を陽性へ変えません。調停でも決まらない型は`pending`を保ちます。

## GM設計支援試験

符号化試験とは別の参加者・課題・解析記録を作ります。v3資料を使う条件と、通常の設計資料を使う条件をGM単位で層別無作為に割り当てる並行群案です。層はGM経験、課題は同じ内容・難度、資料閲覧と作業を含む時間予算は同じにします。両条件間の教材共有と学習持越しを避けるため、主試験では同一GMを両群へ配置しません。

課題担当が型名に依存しない依頼と採点上の必須点を先に固定します。複数課題を使う場合は順番を均衡化し、課題をGM内反復として扱います。A1/A2、D1/D5、E4/E5の識別が必要情報・行動・準備を変えるかは補助の課題比較です。期待型を埋めた数は成果へ含めません。

型名・教材名・作成条件を除いた設計物を、独立した採点者が[外部rubric](gm-rubric.md)で採点します。採点者の条件推測も残し、条件を知らない状態で採点できた範囲を報告します。記録には欠落した必要情報、行動効果、Q/D混同、決着の範囲、成果の固定、総準備時間、負担を残します。採点の合意前一致度も評価し、調停得点で置換しません。

設計支援の支持判断には品質差と時間コストの両方を使います。詳細は[解析案](analysis-plan.md)へ固定します。型の分類一致が高いことをGM効果に置き換えません。

## プレイ体験差試験

GM比較とは別実験です。最初に推定する効果を一つ選びます。v3利用の効果ならGMによる設計を介する全体効果、情報・選択の操作ならその操作の効果、提示演出の操作ならその演出の効果です。v3利用と演出と情報を同時に変えて一つの原因へ帰属しません。

初回案は、GMの教材条件を固定し、同じ問題状態と脅威・判定難度・時間・提示を使って情報／選択の一要因だけを操作します。卓単位で無作為割当し、卓内のプレイヤーは同一条件です。GMが複数卓を担当する場合はGM内相関も扱います。順序と経験を記録し、同じシナリオを知る参加者の扱いを先に固定します。

事前に危険認識と予期損失、該当場面の直後に可能だと思った行動・主体性・恐怖・不気味さ・嫌悪・驚き・悲嘆、終了直後に達成感・納得と決着認識を測ります。測定のための中断方法を全条件でそろえます。尺度の文言・範囲・方向、主指標と時点は固定前の未決事項です。未測定と無反応を区別します。

結末は安全な解決、未解決、損失による終結を別記します。主体性が高く恐怖が低い結果も、そのまま報告します。途中終了・撤回と理由不明の欠測を保ち、回答を推定して埋めません。参加者の安全・同意条件が未合意の間は実施保留です。
